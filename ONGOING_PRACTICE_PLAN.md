# Ongoing Python interview practice

This plan continues beyond the original company-specific preparation window. It reflects the format described in the October 12 shared thread: conventional DSA plus simulations, machine coding, practical data work, and requirement changes.

## Default 90-minute session

| Time | Work | Evidence |
| ---: | --- | --- |
| 45 min | DSA Easy/Medium | Correct implementation, tests, complexity |
| 27 min | Practical or machine-coding module | State/data model and one extension |
| 18 min | Explain and revise | Verbal approach, edge cases, follow-up change |

This is approximately a 50% / 30% / 20% split. Change the ratio based on actual interview feedback and observed gaps.

## Readiness standard

For a problem to count as independent practice, record evidence that you:

1. identified the main data structure without a substantive hint;
2. wrote working Python in 20–35 minutes;
3. added a meaningful edge-case test;
4. explained time and space complexity correctly; and
5. handled one changed requirement without replacing the entire design.

Use `progress.md` for actual attempts. Do not mark a task complete merely because its supplied tests pass.
